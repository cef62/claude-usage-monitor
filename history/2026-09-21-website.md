## Summary

Added a static product site under `site/` (bare Astro, no theme, no UI library) deployed to
GitHub Pages at `https://cef62.github.io/claude-usage-monitor/`. The landing page pitches the
app, shows the four README screenshots, and links two download buttons built from
`package.json`'s version to the matching release assets, plus an "all releases" link. The Guide
page renders `README.md` and the Changelog page renders `CHANGELOG.md` directly — both files
stay the single source of truth; the site never copies their content. Two hand-written
remark/rehype plugins (`site/plugins/remark-commit-links.mjs`, `rehype-repo-links.mjs`) rewrite
CHANGELOG commit-hash bullets into commit links and README's repo-relative image/link paths
into GitHub raw/blob URLs, covered by `test/site-plugins.test.ts`. A new `pages.yml` workflow
builds `site/dist` and deploys it on push to `main` when `site/**`, `README.md`, `CHANGELOG.md`,
`package.json`, `pnpm-lock.yaml`, `docs/screenshots/**`, or the workflow itself change, so every
Version Packages merge (which touches `CHANGELOG.md` and `package.json`) redeploys the site with
the new version and release notes. `pnpm site:build` was added to `ci.yml` so a broken site
build fails PRs too.

## Initial Request

Give the project a small public web presence: a landing page with downloads, a guide (the
README, rendered, not copied), and a changelog, deployed automatically on GitHub Pages,
redeploying whenever a release ships. Scope explicitly excluded: custom domain, search,
sidebar, versioned docs, analytics, RSS.

## Final Notes

- Astro 7's default markdown processor dropped built-in remark/rehype plugin support, so
  `@astrojs/markdown-remark` (official, same org as `astro`) was added specifically to keep
  `markdown.processor: unified({...})` working — a dependency the original plan did not call
  out by name.
- The markdown import's `Content` component is a **named** export (`import { Content } from
  '...md'`), not a property of the default export as first assumed; `61eda2b` fixed a stale
  comment about this once it was confirmed working.
- `import.meta.env.BASE_URL` carries no trailing slash in the installed Astro version, so
  `Base.astro` and `index.astro` both normalize it (`base.replace(/\/$/, '')`) before
  interpolating `${base}/guide/`-style links — without it, links glue into
  `/claude-usage-monitorguide/`.
- `biome.json` excludes `*.astro` entirely rather than tuning rules, because Biome misreads the
  frontmatter script section's exports as unused imports; this is a known Biome/Astro gap, not
  a project-specific one.
- `pnpm-workspace.yaml` needed `allowBuilds.esbuild: true` for `pnpm install --frozen-lockfile`
  to succeed non-interactively in CI — pnpm's build-script approval gate otherwise blocks
  esbuild's postinstall (astro's bundler) on a fresh install.
- Folded into this task from Task 2 review: `pnpm-lock.yaml` was missing from `pages.yml`'s
  path filter, so a lockfile-only bump (e.g. bumping `astro`) would not have triggered a
  redeploy; added.
- Custom domain, search, sidebar, versioned docs, analytics, and RSS are explicitly out of
  scope per the plan.
